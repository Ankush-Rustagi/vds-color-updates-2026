# Design Platform Strategy

Verkada Design System is moving from fragmented legacy colors to a **single semantic token layer** defined in Figma Collection. Color v2 is the first platform-wide cut of that strategy: one token name, light and dark values, consumed by Figma components and Command code through the same naming rule.

## Primary objective

**Semantic tokens replace raw hex and per-component overrides.** Components bind to names like `--button/background/alert`, not `#CB2939`. Primitives (palette steps) resolve into semantics at the component level. Teams migrate surfaces; Design System owns the Collection.

## What is in scope (Color v2)

- **566 semantic color tokens** (light + dark)
- **237 color primitives**, size, and effects tables from [Figma Collection]({FIGMA_LINKS.collection})
- **Reference migration patterns:** Alert Button, Checkbox (from Color Updates deck slides 6, 8–9)
- **Per product line examples** under Teams (Cameras, Access Control, Alarms, etc.)

## What is out of scope (for now)

- Full Verity component library rewrite (Melina's Storybook work continues separately)
- Production dark mode sign-off (Figma column is **Dark Mode Testing**)
- Typography, motion, and non-color tokens beyond the Collection export

## Design platform principles

1. **Figma Collection first.** If it is not in Collection, it is not a token.
2. **Semantic over primitive in product UI.** Primitives are for scales; components consume semantics.
3. **No local colors.** Flag gaps to Design System; do not ship team-specific hex.
4. **Reference before rollout.** Validate Alert Button + Checkbox patterns, then expand by surface.
5. **AI-compatible docs.** DESIGN.md and Storybook stay aligned so Claude Design and OpenDesign agents use the same rules.
